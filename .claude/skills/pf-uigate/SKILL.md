# UiGate — the floor, then the ceiling

Both tools ship with the framework and are **synced**, not authored per SKU: they land at
`Tools/pf/` and carry a `GENERATED by PrototypeFramework <version>` header. Editing one there is
pointless — the next `agentdocs` sync reverts it and `--check` is red until then. Change it in the
framework repo (`Documentation~/agent/tools/`). See `docs/framework/sync-contract.md`.

What stays in the SKU is the **data**: `Tools/UiGate/probes/`, `contracts/`, `references/`,
`captures/`, `judge-calibration.md`, `tuning/` (calibration suites, baselines, run history).
Coordinates and token names belong to one game; the tools do not.

## The capture harness — where `captures/*.png` and `probes/*.layout.json` come from

Both gates read a capture. The framework also ships the thing that **takes** it:
`ClassicSpins.PrototypeFramework.Editor.Capture` (menu **Framework/UiGate/Run All Capture Fixtures**).
EditMode only — a preview scene, one manual render, no play session, no batchmode.

| The framework owns | The SKU owns |
|---|---|
| `CaptureRig` (preview scene, ruler-correct camera + world-space canvas, uGUI settle, URP-safe render, PNG) | one `ICaptureProject`: fixture folder, `TokenSource` (a token file, or `null` when every probe reads its hex off the prefab), `Load` (parse) and `Plan` (validate against the game's rules) |
| `CaptureHarness` (fixture → PNG → layout → `--generate` → probe, `0/1/2`, negative fixtures) | one surface per drawable screen: `CaptureSurface<TContext>` with `Id`, `Build` (END state, no time) and `Publish` (probes + masked regions after the settle) |
| `CaptureSurfaceRegistry` / `CaptureProjects` (discovered through `TypeCache` — nothing to register) | its `*.fixture.json` documents and, if its surfaces need game state, a `CaptureContext` subclass returned from `ICapturePlan.CreateContext` |
| `ProbeLayoutEmitter`, `PixelProbeRunner`, `RegionSeparation`, `AlphaMaskedLuminance`, `LabelFitProbe` | the field assertions (EditMode tests) that read `CaptureRigResult.Pixels` / `Regions` |
| `DrawableInventory` + `ArtProbeSampler` (the coverage floor's measurements: every drawable, its visible and colour-measurable pixels, its texture-derived expectation, the label mask and the coverage sidecar) | each exemption from coverage and its reason (`context.Exempt` / `ExemptHierarchy`), and a `Target` on each point probe |

- **Entry points.** `CaptureHarness.RunAll(out report)` (the menu) or `CaptureHarness.Run(
  CaptureHarness.FixturePath("<stem>"))` for one fixture — the call an EditMode test or an MCP
  `script-execute` makes. Each fixture declares its `outcome` (`captured` · `flat-capture` ·
  `refused`), and `RunAll` is green when every fixture met its own declaration.
- **Outputs, fixed paths.** `Tools/UiGate/captures/<stem>.png` (regenerated, git-ignored), and
  beside it — regenerated and git-ignored with it — `<stem>.mask.png` (the coverage floor's 24-bit
  label mask) and `<stem>.coverage.json` (every number the rig MEASURED: visible, unshared, mapped
  and colour pixels, where the texels came from, expected Lab, which drawables each point probe's
  centre landed on). `Tools/UiGate/probes/<stem>.layout.json` + `<stem>.json` (committed, schema v2)
  carry structure only — ids, paths, render paths, bounds, exemptions, targets — so they do not
  churn between machines or build targets. A surface that draws
  anything goes through the probe tool even with no point probe — coverage settles it; only a frame
  with no drawable in it at all is settled by the flat-capture check alone.
- **Extents are names.** A fixture says `"extent": "base"` (1080x1920), `"tall"` (1080x2400) or `"wide"`
  (1440x1920). Base and tall are width-anchored (1080 world units across; a taller extent only adds
  vertical bleed); wide is height-anchored (1920 units tall; the tablet's extra width is horizontal
  bleed). One capture pixel is one world unit at every extent.
- **The ground is the SKU's token** (`ICapturePlan.Ground`), never a rig default — an empty-region
  probe must read the colour the game draws.
- **Anything a surface creates in code** (`new Texture2D`, `Sprite.Create`) goes into
  `context.Temporaries`; the rig destroys it in its `finally`.
- The SKU's Editor assembly (and its EditMode test assembly) reference
  `ClassicSpins.PrototypeFramework.Editor` for this.

## The two gates

| | Floor | Ceiling |
|---|---|---|
| Command | `Tools/pf/pixel-probe.py` | `Tools/pf/visual-judge.sh` |
| Question | *Is this wired up at all?* | *Does it look right?* |
| Answers with | arithmetic — CIE76 ΔE against a design token | a vision model, against an approved reference |
| Costs | nothing, and answers the same way every time | a model call and quota |
| Story kind | `kind: function` → `## Render Floor` | `## Visual Contract` — `kind: finish`, and every `kind: function` story that renders a surface (its own parts) |

**Run the floor first, always.** It is free, it is reproducible, and a floor failure makes every
ceiling verdict meaningless — a frame that did not render comes back with every contract row VIOLATED
and every one of those verdicts names the wrong cause.

```sh
Tools/pf/pixel-probe.py --capture Tools/UiGate/captures/<surface>.png \
                        --points  Tools/UiGate/probes/<surface>.json

Tools/pf/visual-judge.sh --spec <spec.md>        # inputs come from the contract's own block
```

**The judge's inputs live in the contract, not on the command line.** A `## Visual Contract` ends with
one fenced ` ```visual-judge ` block naming every image and note the rows need:

```visual-judge
root: <design package>                              # base for reference: and notes: paths
reference: mockups/<surface>-01.png | approved mockup — rows 1-8
reference: imports/<benchmark>.png | finish benchmark — row 9 only
capture: Tools/UiGate/captures/<fixture>.png | fixture <fixture> — rows 1-9
notes: DIVERGENCES.md#<surface>
```

**Rows carry a fidelity dimension.** Each row starts with one tag — `[type]` `[scale]` `[layout]`
`[density]` `[art]` — and `[type]` / `[scale]` block while the other three are **report-only**
(`UIGATE_REPORT_DIMENSIONS` in `judge.conf`): their VIOLATED is rewritten `REPORTED`, archived, and
never sets exit 1, never counts in `LOOP:`, never HALTs. Copy wording and data in a mockup are
illustrative; the judge is told so whenever a row is tagged. How to write each kind of row, and why
presence-only rows passed screens that looked nothing like their mockups:
`docs/framework/recipes/visual-contract-judge.md` › "Write the rows". At the end of a run,
`python3 Tools/pf/review-pack.py` turns every spec's contract and its latest judge record into one page
(`Tools/UiGate/review/index.html`) for the human review: run it ONCE, by the session that closes the run
or the epic — never inside the implement → capture → judge loop and never per story. REPORTED rows land
only there. A surface flagged "contract changed after this record" must be re-judged before its rows are
trusted. Never act on a REPORTED row from the page yourself, and never reword a row to match it — the
review is the person's.

Every caller — the implementing stage, the audit, the review lens, a measurement — runs the same
`--spec <spec.md>` and so judges the same images. A row that compares against an image the judge was
never handed returns CANNOT-TELL forever, or worse, SATISFIED on anything; the block is where that is
prevented once instead of remembered at every call site. `--capture`, `--reference` (both repeatable,
`path|label`) and `--notes file#section` still work and are added to the block. The prompt carries a
numbered legend of every image, so each V-line cites which capture and which reference it read.

**Pin the model.** The judge runs Codex with `--ignore-user-config`, which also drops the user's own
model and effort. Put `VISUAL_JUDGE_MODEL=` and `VISUAL_JUDGE_EFFORT=` in the SKU's
`Tools/UiGate/judge.conf`; a catch rate measured on one model says nothing about another.

**Let the judge own its clock.** It sends each image downscaled to a 768 px short side and encoded
as JPEG q90 4:4:4 (`UIGATE_JUDGE_FORMAT`; any image with transparency stays PNG). That is 2.1 MB for
nine images, against 8.3 MB as PNG. Measured on the same inputs, interleaved in the same time
windows: 63–76 s per call as JPEG, 398–860 s as PNG, with the same token count. Every model call runs
under one ceiling for the whole run, `UIGATE_JUDGE_TIMEOUT` (default 840 s). When it fires, the
judge exits `2` saying "no answer within Ns". So:

- **Never wrap the judge in a shorter `pf-timeout`.** A run killed early can never answer, and the
  next attempt then looks like a dead transport. Story 8.1 lost 104 minutes and an escalation to
  seven such attempts, capped at 280–900 s, each on a call that needed up to 14 minutes as PNG.
- **Give the host enough room:** Claude Code's `Bash` defaults to a 2-minute cap. Pass
  `timeout: 900000` on the call that runs the judge.
- `ERROR: Reconnecting… n/5` is the transport retrying, not a failure. It answers or it hits the
  ceiling.

**Let it vote.** The model is not deterministic. Measured 2026-09-23: an input judged all-SATISFIED
that morning came back with three rows VIOLATED in 3 of 3 re-runs that evening, on byte-identical
bytes. A single call, and the cache hit that replays it, can therefore sign off a borderline row by
luck. So the judge votes by default: `UIGATE_JUDGE_SAMPLES=K` (default **2**; set it in `judge.conf`) makes K calls in parallel, and adds one call at a time
for any row they split, up to 2K-1 in all. A row counts only when K calls agree. A row that never
reaches K comes back `VIOLATED — unsettled`, with its votes on the line. `K=2` costs about 75 s of
wall time as JPEG and 2–3× the judge tokens. Raising K changes what the calibration measured, so
re-run it.

`--dry-run` on the judge does every check, prints the prompt and the exact `codex` argv, and stops
before spending a model call. Use it whenever you are verifying wiring rather than pixels.
`--caller <name>` tags the archive record (stage, audit, lens…) so a run's judge calls can be
counted per call site; `--measure` samples the same input repeatedly without the cache or the HALT
check, for measuring the judge rather than the UI.

## Exit codes — two of them are not about the UI

`CliConventions.ExitCode`, as everywhere else: `0` Ok · `1` Drift · `2` Error. The judge adds `3`.

| Code | `pixel-probe.py` | `visual-judge.sh` |
|---|---|---|
| `0` | every probe inside tolerance | every blocking row SATISFIED or CANNOT-TELL (`REPORTED` never blocks) |
| `1` | a probe outside tolerance; a drawable uncovered, never reaching the frame or colour-unmeasurable; a probe missing its target (the harness also: a `SLICE` finding on a surface not in `sliceDebt`) | at least one row VIOLATED |
| `2` | could not run — **including BROKEN CAPTURE**, an exemption with a blank reason, and an art drawable the harness could not map onto its own pixels (`unmapped`) | could not run — no `codex`, no contract, **BROKEN CAPTURE** |
| `3` | — | **HALT**: the loop is not converging |

**`2` is a broken capture, not a wrong UI.** The flat-capture check runs *first* and outranks every
probe: a frame that is very nearly one flat colour did not render, and reporting that as `1` would
name a UI defect that does not exist. This is not hypothetical — `Tools/UiGate/judge-calibration.md`
records the Game View's render texture reading back a uniform `RGBA(0.098, 0.098, 0.122, 1)` across
the whole frame, and the loop that met it spent model calls to be told, wrongly, that the UI was
broken. **Fix the capture, then re-run.** Never "fix" the UI in response to a `2`.

**`3` is HALT: the row is asking the fixture for something it cannot give.** The judge reads its own
archive back before calling the model. Same row VIOLATED in each of the last two runs *and* this
capture byte-identical to the last one ⇒ the model has nothing new to look at and will answer exactly
as it did twice already. **Stop coding and re-read the row.** A row that needs a state the fixture
never enters, or an asset the fixture does not load, is a contract defect — reword the row or change
the fixture. Iterating the View is how this spins four rounds for nothing.

Every judge run archives to `Tools/UiGate/captures/<surface>/<stamp>-<verdict>.{png,md}`: the capture
as judged, the model, the reference, the V-lines, and the hash of the contract that produced them.
That archive is what the HALT check reads; it is also the only record of where a drift started.

## Producing the probe data for a new SKU — five steps

The points file is **machine-generated**. Nothing in it is hand-typed, which is the whole reason the
numbers in it can be trusted.

1. **`bmad-ux` names the elements.** For each surface it produces the list of things on it and the
   design token each one is expected to be drawn from. That is the *what* — it exists before any code.
2. **The story that builds the surface knows the real rect.** It writes the field assertions, so it
   already holds the anchors, the sizes and the parenting. That is the *where*.
3. **The surface publishes; the harness emits `Tools/UiGate/probes/<surface>.layout.json`**
   (schema `pixel-probe-layout/v2`) from (1) and (2). Nothing in it is typed: the surface's
   `Publish` adds a `CaptureProbePoint` per element it means to colour-check (rect resolved from the
   sprite's alpha or read off the settled `RectTransform`, plus the token NAME — or, when the look is authored on the prefab, a hex read off the
   drawing Graphic by `CaptureProbePoint.FromGraphic`, never a typed one — plus the `Target` it
   reads), and its explicit exemptions; the harness adds the drawable inventory, writes the layout,
   and runs step 4. No coordinate in pixels and no hex value is ever written by hand — a hand-written
   layout is a v1 file, and a v1 file never declares coverage.
4. **Generate the points file:**
   `Tools/pf/pixel-probe.py --generate Tools/UiGate/probes/<surface>.layout.json --out Tools/UiGate/probes/<surface>.json`
5. **A token change means regenerate, never hand-edit.** The generated file says so in its own
   `generated` field. A hand-edited points file is a gate that certifies whatever it was edited to
   say — the failure mode this whole pipeline is built to avoid.

## Coverage — every drawable is probed, art-probed or exempted

A floor that probes only what its author pointed at certifies only that. Measured on one SKU: 5 of 6
probes on a gameplay fixture read one token on one render path, and no goods, cabinet or backdrop
pixel was checked — a wrong material or a colour-space slip on textured art passed. So the harness
inventories **every drawable that renders into the capture** (each enabled `Renderer` and uGUI
`Graphic` whose bounds reach the frame) and `pixel-probe.py` requires each one to be covered by
**at least one** of these (an exemption wins over the rest):

| Covered by | How | Settled when |
|---|---|---|
| **Art probe** (automatic) | a Simple `SpriteRenderer` or `Image` (incl. `preserveAspect` and `overrideSprite`; with no sprite, the material's main texture), a solid-colour `Image`, a `RawImage`, drawn through `Sprites/Default`, `UI/Default`, URP `Sprite-Unlit-Default` (or `Sprite-Lit-Default` while no 2D light is in the scene) — read off `materialForRendering`, the material uGUI really draws with: its own texel × vertex tint × material `_Color`, composited over the same pixel rendered without it. The texels are decoded from the texture's **source PNG/JPG**, never the import | on its **colour-measurable** pixels, the capture's median CIELAB is within **4 dE76** of the median its data implies (at least 16 such pixels) |
| **Presence probe** (automatic, text only) | a non-empty `TMP_Text` (world or UGUI) or `UI.Text` | at least **16** pixels change when it is removed — no colour expectation |
| **Attributed point probe** | `new CaptureProbePoint(…, target: renderer)`; a legacy probe with no `Target` is credited to the smallest **non-exempt drawable visible at its centre** (the generator's `target` for it is only a guess from bounds) | it lands: its centre is on one of the drawable's visible pixels. A targeted probe that does not is **`probe misses its target`** (exit 1); a legacy one with nothing drawn at its centre covers nothing |
| **Exemption** | `context.Exempt(drawable, "reason")` or `context.ExemptHierarchy(root, "reason")` in `Publish` | always — the reason is printed on an `EXEMPT` line |

- **Visible and colour-measurable are two different sets.** For each drawable the rig re-renders only
  its pixel bounds with it removed (`CanvasRenderer.cull` / `Renderer.forceRenderingOff`, a stencil
  mask's own colour through `showMaskGraphic` — never `enabled = false`, which would dirty layout) and
  diffs. **Visible** is every pixel that moves by more than 8/255, shared or not: that is what "never
  reaches the frame" and the presence probe count. **Colour-measurable** is the subset no OTHER
  drawable also moves, where the drawable's own texel × tint has alpha — the only pixels whose colour
  is exactly predictable, so a soft shadow or a translucent sprite over the ground is checked exactly.
- **What the art probe catches — and what it never does.** It catches **render-path faults**: a
  colour-space slip, *including a texture imported with the wrong sRGB flag* (the expectation is
  decoded from the source file, so the import cannot bend it the same way it bends the render), a
  shader or blend that does not draw texel × tint, occlusion, a missing sprite. It never catches a
  **wrong tint or colour VALUE**: the expectation is built from that same value, so a tint set to the
  wrong token passes. That stays a field assertion against the design token. When a texture has no
  PNG/JPG behind it (an atlas page in edit mode, a PSD, a texture made in code) the texels come
  through the import instead — and so do they when the importer rewrites texels the file does not
  have (alpha from grey, PNG gamma ignored, a channel swizzle, a single-channel texture); the sidecar
  records `texelSource: "import"` and the art line says
  `texels via the import` — an import-flag fault is invisible on that drawable.
- **Colour-unmeasurable, and the overlay idiom.** A drawable that is visible but has fewer than 16
  colour-measurable pixels — the board under a pause dim, a box under a soft shadow — cannot be
  art-probed: which of two drawables is on top of a pixel is unknown without a sort model. It is
  reported as `colour-unmeasurable` (exit 1, with its unshared pixel count), never as "never reaches
  the frame". Cover it with a point
  probe whose `Target` names it, or exempt the overlaid subtree once:
  `context.ExemptHierarchy(boardRoot, "under the pause dim in this state; the judge reads it")`. One
  `ExemptHierarchy` line per overlaid subtree is the expected shape — not one `Exempt` per sprite.
- **`unmapped` is a harness defect, never an overlay.** An art drawable whose own unshared pixels —
  shared with nothing — do not map onto its own quad (`mapped` < 16 ≤ `unshared` in the sidecar) is
  `ERROR | art … unmapped` and exit `2`: the harness mapped that drawable's texture wrong. Report it
  against the framework with the sidecar attached; never exempt it, which would hide the bug.
- **What draws nothing by design is not counted:** a blank text; a `Mask` graphic with
  `showMaskGraphic = false`; a `SpriteMask`; a Graphic its `RectMask2D` already culled; anything
  under a disabled `Canvas`; a **non-text** Graphic at effective alpha 0 (a hit area such as
  `PF/Blocker`); a `SpriteRenderer` with no sprite or at alpha 0; a Renderer whose
  `forceRenderingOff` is already set; a world `TextMeshPro` whose `MeshRenderer` is disabled; anything
  with a zero-width or zero-height rect. A text at alpha 0 IS counted, and fails its presence probe. A
  probe or exemption that names one of these finds nothing: a `Target` is refused (exit 2), an
  exemption is a WARN.
- **Refused at capture (exit 2, named):** a Graphic on a **Screen Space** canvas — its rect is in
  screen pixels, not on the capture's ruler, so parent it under `context.Canvas`; a `Target` that
  draws nothing itself (a `LayoutElement`, a `Button`) on a GameObject carrying **two drawables** —
  name the one it reads; a point probe with a **blank label**; two probes sharing one **rect name** with different rects; two drawables on one
  hierarchy path are not a refusal — they get `Path` and `Path [2]` (counting on past any sibling
  literally named that).
- **Exit codes.** An uncovered drawable is `1`, and its line names the hierarchy path and the render
  path (`<component>/<shader>`). A drawable that **never reaches the frame** — fully occluded,
  culled, alpha 0, a text with no font or drawn in its ground's colour — is `1` too, and so is a
  colour-unmeasurable one with no point probe, and a targeted probe that misses its target. An
  exemption with a blank reason is `2`, naming the drawable; so is a mask or sidecar that is missing or
  belongs to another capture. The flat-capture check still runs first and outranks all of it.
- **Not eligible for an automatic probe:** a Sliced image drawing a bordered sprite, a tiled or
  filled image with a sprite (with no sprite, or a Sliced one with a border-less sprite, uGUI draws a
  plain quad and it IS art), an Image with `useSpriteMesh`, a material whose `_MainTex` scale/offset is
  not the identity, a tiling `RawImage` `uvRect`, a `SpriteRenderer` with a `MaterialPropertyBlock` or
  more than one material, a line, a particle, a lit or custom-shader mesh (including a Graphic whose
  `materialForRendering` is not a default UI shader), a rotation-packed sprite, anything an
  `IMeshModifier` (Shadow, Outline…) rewrites, a Graphic with an active `IMaterialModifier` other than
  its own stencil handling. Each needs a point probe with `Target` or an exemption with a reason. **No class is ever
  exempted by default** — an exemption is a sentence a reviewer reads. An exemption that matches no
  drawable is a WARN: it exempts nothing.
- **`ProbePurpose.Presence` is a lint tag, nothing more.** A `Presence` probe still reads its colour
  and still fails outside tolerance; the tag only takes it out of the redundancy lint. Two
  `ProbePurpose.Colour` point probes on the same token (or the same hex, with no token) and the same
  render path prove one thing twice — the legacy 4-badge layout. The tool WARNs and leaves the exit
  alone; keep one colour probe and tag the rest `Presence`. (Retargeting them does not silence it
  while they still read one token on one render path.)
- **What it still cannot see:** a wrong sprite with a near-identical palette, text colour, and
  composition. Those stay with field assertions and `visual-judge.sh`.
- **v1 files keep working.** A `pixel-probe/v1` points file is settled exactly as before and prints
  that coverage was not declared. Re-capture through the harness to get v2.

### The first red run after upgrading to 0.7.0

A SKU fixture that was green on 0.6.x can come back exit `1` on its first capture after the upgrade.
Nothing in the UI changed: the floor now looks at drawables nobody had pointed a probe at. Work the
report top-down, one line at a time, and never "fix" a View to silence it:

1. **`FAIL | art` with a dE** is a real finding on art the old floor never read — a colour-space
   slip (often a texture imported with the wrong sRGB flag), a shader or blend that does not draw
   texel × tint, something drawn over it. Treat it as a bug. (A wrong tint *value* never shows here;
   that is the field assertion's.)
2. **`ERROR | art … unmapped`** (exit 2) is the harness, not the SKU: report it, never exempt it.
3. **`UNCOVERED`** names a sliced panel, a line, a particle, a lit mesh. Add a point probe with a
   `Target` on it (its token colour — the probe checks it whatever its purpose), or
   `context.Exempt(drawable, "<why it cannot be probed>")`.
4. **`colour-unmeasurable`** is a subtree under an overlay (dim, shadow, glow). One
   `ExemptHierarchy(root, reason)` per overlaid subtree, or a targeted point probe.
5. **`never reaches the frame`** is either a defect (occluded, no font, alpha 0) or the state the
   fixture shows (a board hidden behind a panel): fix it, or exempt it saying which.
6. **`probe misses its target`** is a legacy probe whose rect never sat on the drawable it now
   names: aim it, or retarget it.
7. **`WARN`** lines (redundant probes, unused exemptions) change nothing; clean them up in the same
   pass while the surface is open.

Commit the regenerated `probes/*.layout.json` and `*.json`; they carry no measured number, so a
second capture on another machine leaves them byte-identical.

## The rect half — the layout snapshot and the layout lint

The prefab owns every per-node look value, so the rect a probe addresses is proven by two Editor-side
guards rather than by a test that pins a number:

- **Snapshot** (`PrefabLayoutSnapshot`, `prefab-layout-snapshot/v1`, `Tools/UiGate/layout/`). Written
  ONLY on a Prefab Mode save (`PrefabStage.prefabSaved`, plus every prefab that nests the saved one) or
  by `Framework/UiGate/Snapshot All Prefab Layouts` — never on import, script save or a test run. It
  stores local RectTransform fields and look fields, never screen coordinates, so one snapshot holds at
  every extent. `PrefabLayoutAssert.Diff(boundInstance, prefabPath)` names node, property, snapshot vs
  bound value; nodes marked `LayoutDriven` skip exactly their driven properties; runtime clones are not
  prefab nodes (their template is). Doctor check 17: a missing or stale snapshot is Drift.
- **Edit survives bind** (`PrefabLayoutAssert.EditSurvivesBind(instance, bind)`): offsets every non-driven node's
  `anchoredPosition` / `sizeDelta`, TMP `fontSize` and `Graphic` colour by a node-specific delta, runs the View's bind
  on the same instance, and names each property the bind overwrote. A snapshot diff proves the View wrote the value the
  prefab holds; this proves it did not write it at all — a View that copies a struct of numbers onto its nodes passes the
  first and fails this one. Rect axes a uGUI layout component drives are skipped.
- **Lint** (`UiLayoutLint`, `Tools/UiGate/ui-rules.json`, `ui-rules/v1`): inside the visible rect by
  `pad`, touch floor, no overlapping sibling Selectables, label fit, font floor — per extent named in
  the rules file (`base`, `tall`, `wide`). `PrefabLayoutAssert.Host(extent)` builds the host canvas.
- **9-slice lint** (`NineSliceLint`, run by `CaptureRig` on the BUILT capture scene after the settle —
  never on prefab YAML): every enabled sliced `Image` and Sliced/Tiled `SpriteRenderer` against the
  policy its sprite declares in `ui-rules.json` — `slices` (sprite name → `fixed` | `height`),
  `sliceTolerance` (default 0.2) and `sliceDebt` (`[{surface, ref}]`). Rules: `slice-scale` (corner
  scale off the policy by more than the tolerance), `slice-clamp` (an axis whose borders exceed its side,
  which Unity squashes alone — `NineSlice.Apply` raises the multiplier uniformly instead),
  `slice-undeclared` (a bordered sprite not in `slices`), `slice-mesh` (a sliced renderer on a Tight
  mesh). No `slices` key ⇒ only `slice-clamp` / `slice-mesh` run. Each finding is a
  `SLICE <rule> <node> <sprite>: <measured vs expected>` line in the fixture report and turns an Ok
  capture into exit `1`; an Error stays an Error. A surface in `sliceDebt` logs `SLICE (debt DW-n) …`
  and keeps its code. **The debt list only ever shrinks**: each entry names the deferred-work id that
  owns its fix, and a story that fixes a surface removes its entry in the same change. The rule ids are
  exemptible through `exempt` like the layout rules (a `prefab` scope matches the surface id).
  **Mockups do not paint one sprite at one rim**: a generated mock may draw the same wood panel twice as
  thick on one screen as on the screen its import was rim-matched to. `sliceRims`
  (`[{surface, node, rim, reason}]`) gives that one node on that one surface a rim factor over its
  sprite's policy, measured from the mock and written in `reason`; the View passes the same factor to
  `NineSlice.Apply(image, scale, rim)` (a serialized field, never a literal) and the lint expects it.

## Why the rect is an address, not the thing under test

The obvious objection is that a probe checks a coordinate the same story chose, and is therefore
circular. It is not, because **the rect and the colour are proven by different rungs.**

- **The rect is proven by the layout snapshot** (or, for a data-driven node, a relation test).
  `anchoredPosition`, `sizeDelta`, the parent, the anchors — all of them are numbers the EditMode
  suite reads back directly, exactly, and for free, against what the prefab says. The probe never re-checks any of them.
- **The probe asks one question at that address: is the colour that reached the screen the colour the
  token says?** That is a question no field assertion can answer, because it is not a field — it is
  the output of the whole render path.

So a probe catches precisely the class of failure that is green in every field and wrong on screen:

- the wrong material or shader bound to a correctly placed renderer,
- a colour-space mistake — a linear value written where an sRGB one was meant, or the reverse (ΔE76
  is computed in CIELAB and is most sensitive to L\*, which is exactly what a colour-space slip
  moves),
- MSAA or post-processing altering what a correct colour becomes,
- a renderer that is disabled, or on a camera's culling mask it should not be,
- a `sortingOrder` that reads correctly in the field and still ends up behind something on screen.

If a rect is wrong, the field assertion goes red — and the probe reads the wrong pixel and almost
certainly goes red too, saying so in a different voice. Neither gate is standing in for the other.

**One tolerance, one meaning.** ΔE76 rather than an RGB distance because sRGB distance is not
perceptually even: 20 units apart is glaring in a dark navy and invisible in a cream, so one repo-wide
RGB tolerance is either too tight on the lights or too loose on the darks. ~1 is the just-noticeable
difference, ~2–3 is "a careful eye sees it", >10 is "those are different colours".

## What belongs where

| The claim | Settle it with |
|---|---|
| "the tile sits at x=140, 96 wide" | a field assertion |
| "the ground is the deliberate token, not the rig default" | `pixel-probe.py` |
| "the badge label stays inside its fill" | `visual-judge.sh` |
| "the scale is 0.72, not 0.80" | a field assertion — the judge returns CANNOT-TELL, correctly |
| "the surface reads as finished, not as a wireframe" | `visual-judge.sh` + `pf-visual-design`'s checklist |

A `CANNOT-TELL` row is not a failure and not a pass: it is the signal to **write the field assertion
that settles it**, and to say in the spec which assertion that is. That is how the parameter checks
get derived rather than invented.

## Before either gate blocks anything

The judge's catch rate is a number, not a belief. Run the surface's mutation fixtures past it and
require it to catch each one while passing the clean capture; record the rate **with the model
identity that produced it**, and re-measure when the model or the prompt changes. Until that number
exists, a `VIOLATED` row is a **finding for triage**, not a unilateral block. An exit `2` is never a
pass — a judge that did not run has proven nothing.

The measuring tools ship beside the judge and read the same archive:

| Command | Does |
|---|---|
| `python3 Tools/pf/judge-calibrate.py [--suite Tools/UiGate/tuning/calibration/<surface>.json]` | runs a suite's clean and mutated cases through the judge; writes `judge-calibration.md` (catch rate, false-positive rate, consistency, model) and appends `tuning/calibration-history.jsonl` |
| `python3 Tools/pf/visual-scorecard.py --spec <spec.md> --variant <name>` | scores one finish-story run (fidelity, judge agreement, cost) into `tuning/runs/`. `--compare <story>` lists every scored run. Its pixel metrics take under a second per image pair (they took ~46 s per image before `colourfulness` was made linear). They are a sanity check, not a gate: measured on one SKU, two different mockups scored a higher layout correlation (0.69) than most captures against their own mockup |
| `python3 Tools/pf/review-pack.py [--out DIR]` | one page per run for the human review: references beside captures, every row with dimension / verdict / judge sentence, a surface × dimension grid — reads specs and the archive, never calls the model |
| `sh Tools/pf/promote-reference.sh <surface> <capture.png>…` | files a capture as `references/<surface>/` **only** if an `ok` judge record lists those exact bytes; the verdict travels in `PROVENANCE.md` |

Bounding the loop: **follow the judge's `LOOP:` line** (`continue` / `stop (…)` / `done`) instead of
counting rounds — the policy is the SKU's (`UIGATE_LOOP_POLICY=fixed|progress`,
`UIGATE_LOOP_MAX_ROUNDS`, default fixed 3), and `progress` stops at the first round that clears
nothing. Only judge a capture that changed; one round, one fix pass. The judge enforces the capture
rule itself: an input already judged (same prompt, same image bytes, same model, encoding and sample
count) returns its archived verdict as a cache hit, with no model call and no new round. Exit `3`
stops the loop whose edits never reach the pixels. A cache hit **replays** a verdict; it does not
re-derive one. That is why the number of agreeing samples is part of the key: what gets frozen
should be a settled verdict, not one draw.

A row that stays near 50/50 across samples is not a coding problem. Story 8.1's V13 (the source-row
warning) sat on that boundary: VIOLATED in 6/6 calls on one capture, and 1 in 3 on the shipped one.
The warning and the destination were two warm hues, ΔE 32 apart, where the reference specimen used a
red. Iterating the View does not settle a row like that. A person deciding the treatment does: route
it to the design owner, and write down which way it was decided.

Capturing the frame at all — the play-mode budget, `screenshot-game-view`, `runInBackground`, the FHD
sizing trap — belongs to `pf-gates` and `pf-visual-design`. This skill starts once a PNG exists.
