# Add a service module (a third-party SDK behind an existing framework port)

Full recipe: **`docs/framework/recipes/add-service-module.md`**. The rule behind all of it: **the
framework must not know a module exists, and a module must not know a game exists.**

## 0. The gate before you write anything

| What you have | Where it goes |
|---|---|
| An **external-SDK implementation of a port that already exists** | A module package — this skill. |
| Logic with **no external dependency** | Register it in the SKU installer. No module. |
| A **new port / event type / `BootCap` / RenderLayer / migrator / broker**, or a fifth role | **Spine change** — route it first. |
| **Editor / command-line capability** with no runtime seam (a build pipeline, an importer) | A **tool** module, `pf-module/2` `kind: tool` — §11. |

A module **defines no seam**: it implements an existing port, occupies the installer slot, and may
replace one boot node. It lives in **its own package** — never inside the framework package, never
under `Assets/<Sku>/`.

## 1. Layout — four roles, one gated

```
Packages/com.classicspins.pf-<domain>/
├── package.json        depends on the framework ONLY — never the SDK
├── pf-module.json      the self-description, single source of truth
├── Runtime/Core/       <Domain>.Core     engine-free, ungated: port impl, I<Sdk>Bridge, boot node, preflight rules
├── Runtime/Sdk/        <Domain>.Sdk      GATED by PF_<SDK>: <Sdk>Bridge + PfModuleMarker_PF_<SDK>
├── Runtime/            <Domain>          UNGATED: <Sdk>Installer (ScriptableObject : IInstaller) + Null<Sdk>Bridge
├── Editor/             <Domain>.Editor   editor-only, ungated, #if inside: IModulePreflight
└── Tests~/<Module>HeadlessTests/         globs Runtime/Core/** only — CI step 5c
```

- The **`Sdk` role is the only define-gated assembly** (`defineConstraints: ["PF_<SDK>"]`) and the only
  runtime assembly naming an SDK type. UPM SDKs use `versionDefines` on the SDK package; runtime and
  Editor roles carry the same entry and **no** `defineConstraints`. Manual DLL SDKs instead use the
  framework's `ModuleDefineSync` and no module-symbol `versionDefines` in any role (§2a).
- The ungated runtime role's `#if PF_<SDK>` reference into `Sdk` is legal only because Unity drops a
  reference to an unsatisfied-constraint assembly — cite `UnityCsReference`
  `CustomScriptAssembly.cs:568` → `EditorBuildRules.cs:244, 451-465`.
- References: runtime roles → `CS.PF.{Application, Domain}`, VContainer, UniTask, own assemblies, SDK
  runtime asm. Editor adds `CS.PF.Editor` + the SDK's editor asm. **Never** Presentation, Views,
  Infrastructure, Composition or `Game.*`. No SKU assembly references the SDK.
- The **marker** `internal static class PfModuleMarker_<DEFINE> { }` in the `Sdk` role is how the
  Wizard and Doctor confirm the gated assembly compiled.
- Registry packages, manual `.tgz` packages and `.unitypackage` managed DLLs are supported. Loose
  source in `Assembly-CSharp` remains unreferenceable. DLL SDKs need `overrideReferences: true` and
  explicit `precompiledReferences` in `Sdk`; never reference every auto-referenced plugin implicitly.

## 2. `pf-module.json`

A service writes `schema` `pf-module/1` (a tool is `/2` — §11). Required: `schema`, `id` (== `package.json` `name`), `displayName`, `frameworkRange`
(node-semver), `port` {`interface`, `mode` `replacement`|`additive`, `replacesBootNode` — key required,
`null` if none}, `requires` {`scopedRegistries[]`, `dependencies{}` — **exact pins**}, `define`,
`installer` {`type`, `menu`, `assetPath` with `{sku}`}. Optional: `summary`, `source`, `manualSteps`
(human zone, shown verbatim, never performed), `docs`, **`ports[]`** — every secondary port your
installer registers, as `{interface, mode}`; the `replacesBootNode` key must be absent from an entry
(present at all, even `null`, it is refused — only `port` carries one). `seam:` and `modules --check`
read `port` ∪ `ports[]`; an entry must resolve in the API index and never repeat `port.interface` or an
earlier entry. Declare every port you register — an undeclared registered interface is held by review,
not by any gate (AD-MOD-4).

## 2a. Manual SDK requirements (framework >=0.9.0)

Optional `requires.manualPackages[{package,version}]` and `manualAssemblies[{assembly,version}]` pin
exact versions; DLL versions require plain `X.Y.Z` without prerelease/build suffix, while packages keep
existing exact SemVer policy. Omitted arrays are empty and malformed entries are rejected by field. Tools
keep all requirements empty. Full examples and recovery: recipe §3a.

- **Packages:** download each named `.tgz`, commit inside the project (Git LFS recommended) and manually
  add a project-relative `file:` line to `Packages/manifest.json`. A tarball in `Packages/ManualSdk/`
  uses `file:ManualSdk/<file>.tgz`. Never absolute/outside-repo paths; CI resolves the committed copy.
  Any resolved source at or above the pin satisfies state; `versionDefines` still arms the symbol.
- **Assemblies:** import the vendor `.unitypackage` into `Assets/` through the Editor. Every declared
  DLL must be an explicit `Sdk.precompiledReferences` edge with `overrideReferences: true`. Never
  combine manual assemblies with `versionDefines` arming the module symbol. Name the tested vendor
  release and download destination in `manualSteps`.
- **Version evidence:** inspect on-disk managed `AssemblyVersion`, never loaded assemblies or an
  archive label. Owner Facebook release 18.1.1 reports 18.1.1.0: declare `version: "18.1.1"`. Valid DLLs
  with absent/zero version provide presence evidence only; the checklist names the tested SDK release.
- **Define ownership:** framework `ModuleDefineSync` adds only a declared manual symbol after reload
  when all DLL requirements hold, across installed NamedBuildTargets. It preserves unrelated symbols,
  writes changed sets only and does nothing in batchmode. A symbol shared with a registry-armed module
  is refused; shared manual symbols need all declaring peers' DLLs (`define:` names blocking peers).
  Disk metadata alone is insufficient: imported managed PluginImporter evidence must enable the DLL for
  **Editor plus every installed concrete player target**. Platform-restricted/unimported DLLs are named
  compiler-unavailable facts, conservatively refused; metadata is still inspected without AppDomain loading.
  Pre-delete and pre-move `AssetModificationProcessor` hooks remove affected symbols before compilation,
  including folder deletion, DLL renames and moves into ignored/Editor-only folders. Availability-preserving
  moves cause no write. Discovery/clearing failure refuses the affected mutation with a named diagnostic;
  normal reconciliation isolates unreadable packages. Asset postprocessing schedules later reconciliation;
  it is too late by itself to protect deleted code DLLs.
- **Safe Mode recovery:** out-of-Editor deletion/branch switches can fail compilation before project
  code runs. Remove the declared symbol in **Player Settings > Scripting Define Symbols for every
  installed target**, then restore/import the SDK. Delete SDK assets through the Editor to use the
  pre-delete protection. Doctor reports DLL/symbol mismatches when running.
- **Install stays registry-only:** no download, import or manual dependency write. Numbered manual
  instructions remain accessible while the SDK is absent, after registry work completes, on restart and
  when range/conflict/seam refuses Install. A blocked continuation reports refusal rather than completion.

## 3. Absence refuses — never falls back

The installer always registers **your** port implementation; only the bridge depends on the define —
`#if PF_<SDK>` → `<Sdk>Bridge`, else `Null<Sdk>Bridge`, which **fails every call as a result and logs
the module id**. Never leave the framework fake resolved: `FakeAdsService` auto-rewards. A gated
installer is the same bug (the slotted asset becomes a missing script).

## 4. The shipped fake is the specification

- **`IAdsService`** — `AdVisibilityChanged` at show-start **and** in a `finally` at show-end, through
  **one visibility state** (AD-MOD-12: a slot per surface, each producer closes only its own in a
  `finally`, the fact derived and published on change; a second fullscreen `ShowAsync` is refused
  before it publishes; `FakeAdsService` holds no slots and refuses nothing, so here `MaxAdVisibility`,
  not the fake, is the reference); auto-log
  every outcome via `AdAnalyticsMapping` → `IAnalytics`; track each paid impression as one
  `AdRevenuePaid` (whatever the consent state — the sink applies it). Push readiness (AD-MOD-11):
  one Core state owns placement→unit bindings and one `ready(unit)` (initialized ∧ requested ∧ not
  showing ∧ loaded) behind both `IsReadyAsync` and `AdReadinessChanged` via
  `IAdReadinessChangedPublisher`; bind on `Preload`/`IsReadyAsync`/`ShowAsync` whatever the SDK state; never
  publish a baseline; publish only changes, per unit, to every bound placement; force the settled value
  at init completion. The fake publishes none — `MaxAdReadiness` is the reference.
- **Consuming `AdReadinessChanged` (a SKU offer)** — (1) subscribe first, (2) then `IsReadyAsync(p)`
  once; (3) no fact yet means *ask*, never *not ready*; (4) `IBufferedSubscriber<AdReadinessChanged>`
  is a defect (replays a `default`); (5) offer only while the latest `Ready` ∧ `IAdGate.CanShow(p)` —
  `An_offer_is_hidden_for_a_remove_ads_owner_on_an_interstitial_placement_even_when_ready`.
- **`IAnalyticsProvider`** — never throw; own your retry. A throw is logged as a provider defect and
  the event is lost for that provider, never re-sent. Money comes only from `AdRevenuePaid`, never
  from `AdShown` / `AdRewarded`, and at most one provider sends revenue to a given backend.
- **`IDevTool` (AD-MOD-13, additive)** — an SDK debugger reaches the SKU as a tool, never by reflection:
  one distinct type per tool registered `.As<IDevTool>()` (Singleton factory, never `RegisterInstance`),
  `Id` = `<module-slug>.<tool>`, `IsAvailable`/`Open` read init state and the kill switch at call time,
  `Open` never throws, declared `additive` in `ports[]`. The framework registers none; the SKU injects
  `IReadOnlyList<IDevTool>`, maps `Id` to a `LocKey` and decides which builds expose them.
- **`IAdsPrivacyOptions` (AD-MOD-9, replacement)** — "change privacy settings" re-shows the SDK's own
  consent form. `AdsInstaller` registers `NullAdsPrivacyOptions` (never available, `ShowAsync` false);
  the module replaces it (Singleton factory `.As<IAdsPrivacyOptions>()`, ungated, declared `replacement`
  in `ports[]`). Available = initialized ∧ a supported CMP, read per call; `ShowAsync` never throws and
  refuses (one warning, no SDK call) on a cancelled token, a call already running, an open fullscreen
  slot, unavailable, or a refused exclusive slot; it holds its **own privacy-options slot** until the
  SDK's completion callback (`finally`), ignores the token once the form is up, adds no timeout, and
  writes nothing back. The SKU consumes it behind its own interface and **never re-registers it** (a
  SKU registration shadows the module's). `MaxAdsPrivacyOptions` is the reference.
- `I<Sdk>Bridge` speaks **primitives only**; the state machine lives in `Core` under `dotnet test`.

## 4a. Analytics extensions (AD-MOD-16/17)

- User properties use **`UserPropKey`** (hand-written Domain `readonly record struct UserPropKey(string Value)`)
  and **string** values on both `IAnalytics` and `IAnalyticsProvider`. Framework `UserProps` names are
  `total_coins`, `best_streak`, `matches_won`; a SKU adds static keys in its own Domain class, with no
  manifest or codegen. One Application `UserPropKeyValidator` enforces `^[a-z][a-z0-9_]{0,23}$`;
  `FanOutAnalytics` drops invalid/default names with one warning per name. Properties are consent-gated
  and never buffered. A backend lacking a property API ignores it and warns once per key.
- Implement no-throw **`OnAnalyticsConsent(bool granted)`**, forwarding it through provider wrappers.
  Fan-out observes Track/property/Flush: unresolved sends nothing; first resolved observation and each
  granted ↔ denied transition notify every provider **before dispatch**, isolating each defect. False
  stops native collection and drops held work; true re-enables an already-started SDK. This callback
  never starts an SDK. Startup stays lazy behind granted Analytics consent and native launch collection
  stays off beforehand; never add/replace a boot node for analytics provider startup.
- **`IAnalyticsCommands`** is one singleton `AnalyticsCommandRouter` registered by `AnalyticsInstaller`,
  collecting all `IAnalyticsCommandTarget` registrations safely with none installed. A target declares
  unique ordinal `ProviderId` = module slug (e.g. `analytics-firebase`) and `ports[]` additive. Register
  one provider singleton as both `IAnalyticsProvider` and `IAnalyticsCommandTarget`, so commands and
  consent callbacks use the same SDK state.
- Execute is synchronous, **main-thread**, no-throw:
  `bool Execute(string providerId, string command, IReadOnlyList<KeyValuePair<string, string>> args)`.
  Only SKU **Application/Composition** services or forwarders call it, never a View or Model. Ordinary
  commands require resolved, granted Analytics consent (else false + log); the **router never buffers
  or replays** commands.
  The ordinal **`privacy.` namespace** bypasses consent, but a target **never starts an SDK** for it:
  use started/pre-start SDK API or return false. Unknown id: false, once-warn per id. Duplicate id:
  first registered wins, once-warn at first command. Target throw: provider-defect log + false.
- **True = accepted** now or queued until SDK start. A target may snapshot and hold accepted work
  during startup and must drop it on consent withdrawal. **False = refused** (unknown command, malformed
  arg, unsupported form or consent). Common vocabulary: **`set_user_id`** with **`id`**, and
  **`privacy.forget_me`**. Every provider README documents its support or an explicit unsupported false,
  plus any extra commands. All-backend facts remain `GameEvent` records. Detail and sample:
  `docs/framework/recipes/add-service-module.md` §5a.

## 5. Boot node — replace, never add

```csharp
builder.Register<MaxAdsInitNode>(r => new MaxAdsInitNode(…), Lifetime.Singleton);
builder.Register<BootNodeOverride>(
    r => BootNodeOverride.Replace("AdsInit", r.Resolve<MaxAdsInitNode>()), Lifetime.Transient);
```

`Id` and `Provides` identical, `Required => false`, node registered as itself (never `IBootNode`),
override `Transient`, one module per target. `Reconcile` throws on a changed `Id`/`Provides`, but
nothing checks `Required`. Your module's headless tests pin all three.

**Holding a module's node until the game is ready is the SKU's `BootNodeOverride.Gate`**, never a
wrapper node and never module code: `BootNodeOverride.Gate("AdsInit", _ => ftue.IsComplete, ftueCap)`.
`Reconcile` applies the `Replace` first, then folds every gate into one `GatedBootNode` (`Requires` ∪
extras, predicate AND gates); a gated skip still emits `Provides`; the gate guards first entry only.
(1) **SKU composition only** — a module never registers a `Gate`; the `modulegate` grep fails any
`BootNodeOverride.Gate` reference under `Packages/com.classicspins.pf-*/`, test assemblies (`Tests/`,
`*Tests.cs`) and `~` folders excluded. It is a grep, not a proof: a `using static` or using-alias, a call
split across lines, or one inside an interpolation hole passes it and stays review-held. (2) Every override is a **`Transient`
factory, never `RegisterInstance`**, until DW-35 lands. (3) Reopen with **`RerunFromAsync(<a cap the node
provides>)`** at a scene/dialog boundary — never `ConsentResolved`, never from a tick. Reruns are
serialized FCFS, so this call and the consent driver's never interleave; cancelling a queued call's token
removes it. An awaited rerun may wait for the running one to finish; catch the `OperationCanceledException`
a cancelled queued call throws; never await a rerun from inside a boot node (it waits behind itself). (4) A gate predicate reads **only what its final `Requires` assert**.

## 6. Ads consent is the SDK's (AD-MOD-9)

The replacement node does **not** inject `IConsentService`; the bridge has **no consent setter**;
nothing is written back. `Requires` stays on `ConsentResolved`. **No timeout** over the interactive
flow; `AdVisibilityChanged(true)` before it, `(false)` in a `finally`, via its own consent-flow slot
in that one state (never refused). SDK init + consent run **once per
process**, memoized (never UserData); can-show keys on the bridge's own state, never `IBootStatus`.

- **One consent UI per region** — in GDPR regions the SDK's form is the only consent form, for any
  purpose; the SKU draws none beside it.
- **ATT is raised only by the SDK flow**, never by SKU code.
- **Declare `FrameworkSettings.ServesNoConsentRegion`** (default `false` ⇒ first-boot consent resolves
  with nothing granted; `true` ⇒ `Analytics` granted). `PersonalizedAds` is never granted by the framework.
- **"Change privacy settings" (`IAdsPrivacyOptions`) is an EEA/UK launch precondition** — the module
  fills the port, the SKU draws the row. Review-held.

## 7. `IModulePreflight`, never a build hook

The build-callback list is **closed** (AD-MOD-6). **Forbidden** in a module of either kind: every
preprocessor and processor — `IPreprocessBuildWithReport`, `IPreprocessBuildWithContext`,
`IPreprocessBuild`, `BuildPlayerProcessor`, `IProcessScene*` / `[PostProcessScene]`,
`IFilterBuildAssemblies`, `IPostBuildPlayerScriptDLLs`, `IUnityLinkerProcessor`, `IPreprocessShaders`,
`IPreprocessComputeShaders`, the legacy `IPostprocessBuild` — the `buildhook` grep fails each. **Permitted**: `IPostprocessBuildWithReport`,
`[PostProcessBuild]`, `IPostGenerateGradleAndroidProject`, `AndroidProjectFilesModifier` — explicit
order, transform-only, never overwriting a different existing value (log module, key, both values). Implement
`IModulePreflight` (`ModuleId`, `Check(BuildTarget)` → `ModulePreflightProblem`s) in the `Editor`
role; keep the decisions in `Core`. The framework's one `ModulePreflightBuildHook` aggregates every
module into one `BuildFailedException`. Mandatory for an SDK-bearing module (optional for a tool) — it is the only
enforcement that reaches a consumer's build. Third-party resolvers by reflection only.

## 8. No defaulted constructor parameters

VContainer resolves every parameter; `ILog log = null` is a hard dependency in disguise.

## 9. Install in a SKU — `Framework/Setup Wizard ▸ Modules`

Bring the package in — an **offer** (dev-linked framework: its checkout's `Packages/`; git-pinned at a
`v<semver>` tag or full commit: the framework's `Editor/Modules/modules.catalog.json`, Add swaps only the
`?path=` value of the framework's own entry — a branch pin offers nothing and says to pin) or a
**git URL** → adds only the module package → reload → row `Partial` → **Install** writes registries and
pins to `Packages/manifest.json` only → **checklist** (`manualSteps`, installer menu, `assetPath`). The
installer-asset drop into the Master Scene slot is human zone. **Doctor check 16** shows the same
state and missing facts by name, and **reports, never blocks**. Distribution: git tag
`<slug>/v<version>`. **A new module adds its `modules.catalog.json` entry** (or a `withheld` id) —
`modules --check` is red naming any in-repo module the catalog misses.

## 11. A tool module — `pf-module/2`, `kind: tool` (AD-MOD-14 / AD-MOD-15)

Editor or command-line capability with **no runtime seam** (first: `pf-build-tools`). Full detail: the
recipe's §13.

- **Schema.** `/1` is a service forever — a new service keeps writing `/1`. `/2` requires `kind` ∈
  {`service`, `tool`} (closed); `kind` in a `/1` file is refused; a `/2` file's `frameworkRange` admits
  nothing below **0.8.6** (`ModuleMetadata.ToolSchemaFloor`).
- **Tool fields.** Required: `schema`, `kind`, `id`, `displayName`, `frameworkRange`, `requires` with
  **empty** `scopedRegistries` and `dependencies`. Optional: `summary`, `source`, `manualSteps`, `docs`.
  **`port`, `ports`, `define`, `installer` are forbidden** — each refused by name.
- **Roles.** `Editor/` → `….Editor` (required) and optional `Editor/Core/` → `….Core`
  (`noEngineReferences`); **both `includePlatforms: ["Editor"]`, never `defineConstraints`**. Non-C#
  payload in a `~` folder (`Shell~/`), found through `PackageInfo.FindForAssembly`; a script never walks
  up to find the project — the root is an argument or environment variable.
- **Free or bound.** Free: no framework reference, no framework dependency, open range. Bound: `Editor` →
  `CS.PF.Editor`, framework pinned **exactly** at its version, range **capped at the next minor**.
- **Reserved slugs** (either kind): `domain`, `application`, `presentation`, `views`, `infrastructure`,
  `composition`, `editor`, `tests`.
- **Driving a build (AD-MOD-15)**: delete the export first; success only on `Succeeded` with zero errors;
  content through `BuildEntry.RunContentBuild(BuildTarget)`; restore settings in `finally`; secrets only
  from the environment; a later stage only after success in the same run; the launcher refuses on
  `Temp/UnityLockfile` (exit `2`) — never run by an agent locally.
- **State.** Only `package:` and `framework-range:` apply — `Ready` when resolved and in range; no
  Install, no installer asset; the checklist is `manualSteps`.
- **Gates.** `modules --check` runs the tool leg; a tool with a `Core` or a payload suite ships
  `Tests~/<Tool>HeadlessTests` (step 5c), the payload suite running as a case inside it.

## If it breaks

| Symptom | Cause |
|---|---|
| The fake still runs | Installer asset not slotted, or the installer assembly was gated. |
| Every call fails, logging the module id | `Null<Sdk>Bridge` — define not armed; Doctor check 16 names the fact. |
| `modules --check` names `define` / `installer.type` / `port.interface` / `id` | `pf-module.json` no longer matches the gated asmdef + marker / the installer class / the API index / `package.json`. |
| `modules --check` names `ports[i].interface` | Not an interface in the API index, or a repeat of `port.interface` / an earlier entry. |
| `greps.sh source` fails `modulegate` | Module code calls `BootNodeOverride.Gate(` — the SKU gates, never the module. |
| Build fails listing `[<module id>]` lines | Your preflight found a half-wired install. |
| Input locked / audio ducked after an ad or the consent prompt | Closing `AdVisibilityChanged(false)` not in a `finally`. |
| Deep link or consent rerun does nothing | A replaced node changed `Id` or `Provides`. |
| "Privacy settings" opens nothing although the module is installed | The SKU registered `IAdsPrivacyOptions` itself and shadows the module's replacement. Consume it, never register it. |
